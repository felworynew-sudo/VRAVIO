# ТЗ: переход на каталожную структуру

Документ описывает переход VRAVIO от «архитектуры в компоненте» к каталожной,
при которой добавление инструмента, окна, команды, правила или плагина — это
**новый файл в известном каталоге**, а не правка существующего кода.

Язык документа — русский, идентификаторы и имена файлов — английские, как во
всём репозитории.

**Как пользоваться.** Каждый этап заканчивается состоянием, в котором проект
собирается, проходит тесты и работает. Между этапами можно остановиться на
любой срок. Отмечайте выполненное прямо здесь: `- [x]`. Строка считается
закрытой, только когда есть и реализация, и автопроверка — то же правило, что в
`docs/requirements.md`.

**Чего этот документ не делает.** Он не меняет поведение редактора. Ни один
этап не должен менять то, что видит пользователь, кроме явно оговорённых
(панель инструментов с `(...)`, окно загрузки). Всё остальное — перекладка.

- **Автогенерация панели настроек** из схемы `ToolOption`.
- **Автоматическая регистрация шорткатов** по группам инструментов.

**Главное.** Поведение инструментов не в файлах инструментов. В
`RasterWorkspace.tsx` — **49 ветвлений по `activeToolId`**, размазанных с

|---|---|
| `raster.clone` | 795, 1167, 1644, 1857, 2025 |
| `raster.move` | 1076, 1304–1310, 1326, 1944 |
| `raster.burn` | 801, 1247, 1356, 1661, 1735 |

**Остальное:**

- `tools.ts` — 30 инструментов одним массивом в одном файле; описание
  декларативное, поведения нет.
- `commands.ts` — 294 строки одним файлом, без разделения по средам.
- **i18n сломан в определениях инструментов**: подпись зашита строкой

- Нет: плагинов, сценариев, кистей, паттернов, JSON темы, движка правил,
  бэкапов с выбором места, десктоп-сборки.

## 2. Границы дисциплины

Самое важное решение всего перехода. Атомарный дизайн применяется **не ко
всему**, иначе производительность упадёт.

| слой | дисциплина | почему |
|---|---|---|
| Интерфейс: поля, ползунки, окна | Атомарный дизайн: атом → молекула → организм | Переиспользование и предсказуемость важнее микросекунд |
| Каталоги: инструменты, окна, команды, правила, плагины | Декларативные данные + реестр по glob | Расширение файлом, а не правкой |
| Движок: пиксели, композит, тайлы, маски | Data-oriented: плоские типизированные массивы, батч-операции | Вызов на пиксель при 2 Мп/кадр дороже всей полезной работы |

**Атомарность движка — это атомарность операций, а не вызовов.** Одна операция
= один файл, экспортирующий функцию над целым буфером. Внутри неё цикл остаётся
плотным, без обратных вызовов и без диспетчеризации по строке.

Все выигрыши, достигнутые проектом, получены снятием абстракции в горячем
пути — компоновкой по тайлам вместо целого холста, хранением слоя в его
собственных границах вместо размера канваса, блочным копированием вместо
двух проходов композита при перемещении, перезаписью только изменившегося
буфера при автосохранении. Переход не имеет права вернуть ни один из этих
приёмов.

**Цифры перепроверены этапом 0** (раздел 5, этап 0) на бенчмарке
`packages/env-raster/src/performance.bench.test.ts` и
`packages/kernel/src/performance.bench.test.ts`, а не взяты по памяти из
более ранней работы, как было при первой редакции этого документа — тогда
композит оценивался в ~14 мс, перемер на реалистичной фикстуре (21 слой,
1920×1080, слои размером с типичный мазок, а не во весь холст) дал ~27 мс.
Расхождение не опровергает саму оптимизацию: композит документа с 46
слоями во весь холст без тайлов стоит 428 мс, с тайлами — 38 мс (это
задокументировано прямо в коде, `render.ts`, комментарий у
`subdivideAbove`) — четырёхкратный запас у порога бенчмарка (×6 от
измеренного) рассчитан от актуального числа, а не от цифры, которая не
подтвердилась.

## 4. Контракты

Контракт — это то, что позволяет реестру подхватить файл. Каждый описан ниже с
обоснованием полей.

### 4.1 Инструмент

Во всех контрактах ниже `label: LocalizedText` — тип из
`apps/web/src/i18n.ts`, добавленный на этапе 1: `{ en: string; ru?: string;
uk?: string; es?: string; de?: string; ja?: string; zh?: string }`, `en`
обязателен, остальные падают на английский через `resolveLabel`.

Набор хуков **выведен из кода**, а не придуман: это те функции, в которых
сегодня стоят 49 ветвлений, с числом ветвлений в каждой.

| сегодняшняя функция | ветвлений | хук контракта |
|---|---|---|
| `handlePointerDown` | 30 | `onPointerDown` |
| `appendBrushPoint` | 6 | `onStrokePoint` |
| `finishGesture` | 5 | `onGestureEnd` |
| `onDropModel` | 3 | `onDrop` |
| `handleWheel` | 2 | `onWheel` |
| `updateBrushCursor` | 1 | `cursor` |
| `beginNavigation` | 1 | `onNavigationStart` |
| `handlePointerMove` | 1 | `onPointerMove` |

```ts
export interface ToolDefinition {
  id: string;                       // "raster.brush"
  order: number;                    // положение в панели по умолчанию
  group?: string;                   // общая ячейка панели и общая буква
  label: LocalizedText;
  icon: string;                     // имя файла в icons/
  shortcut?: string;

  options: readonly ToolOption[];   // как сейчас — панель строится сама

  /** Типы слоёв, на которых инструмент работает. Заменяет RASTER_ONLY_TOOLS. */
  appliesTo: readonly RasterLayerKind[];
  /** Что делает с документом. Читается движком правил. */
  touches: "pixels" | "selection" | "view" | "vector" | "none";
  /** Требует растеризации нерастрового слоя перед работой. */
  requiresRasterized?: boolean;

  /** Прицелы. Первый — по умолчанию; переключение по контексту или клавише. */
  cursors: readonly CursorRef[];

  /** Окно тонкой настройки, если ползунков на панели мало. */
  settingsModal?: string;           // id из modals/
  contextMenu?: readonly string[];  // id команд для правого клика по холсту

  onPointerDown?(ctx: ToolContext, event: ToolPointerEvent): void;
  onPointerMove?(ctx: ToolContext, event: ToolPointerEvent): void;
  onStrokePoint?(ctx: ToolContext, point: StrokePoint): void;
  onGestureEnd?(ctx: ToolContext): void | Promise<void>;
  onWheel?(ctx: ToolContext, event: ToolWheelEvent): boolean;
  onNavigationStart?(ctx: ToolContext, event: ToolPointerEvent): boolean;
  onDrop?(ctx: ToolContext, files: readonly File[]): void | Promise<void>;
  onKey?(ctx: ToolContext, event: KeyboardEvent): boolean;
  onDeactivate?(ctx: ToolContext): void;   // обязателен, если есть состояние
}
```

`ToolContext` — единственная дверь инструмента наружу. Он **не даёт** прямого
доступа к React-состоянию: только документ, вьюпорт, настройки, выделение и
метод фиксации правки. Это и есть то, что делает правило невозможным обойти.

```ts
export interface ToolContext {
  readonly document: RasterDocumentState;
  readonly viewport: Viewport;
  readonly options: Record<string, unknown>;   // настройки этого инструмента
  readonly selection: PixelSelection | null;
  readonly activeLayer: RasterLayer | null;
  /** Единственный путь к пикселям. Проводит правку через движок правил. */
  commit(edit: PixelEdit): Promise<void>;
  /** Всё, что рисуется поверх холста, — только отсюда. */
  overlay: OverlayHandle;
  run(commandId: string, args?: unknown): Promise<void>;
}
```

### 4.3 Команда

Контракт ядра уже есть. Добавляются три поля — **все три нужны для сценариев**:

```ts
export interface CommandDefinition extends Command {
  /** Куда софт вставляет пункт: меню, контекстное меню слоя, панель, палитра. */
  surfaces: readonly ("menu" | "palette" | "layer-context" | "canvas-context" | "toolbar")[];
  /** Аргументы. Без схемы сценарий нечего записывать и нечем воспроизводить. */
  args?: ArgSchema;
  /** Запрещена к записи в сценарий (сама запись, воспроизведение, undo). */
  neverRecord?: boolean;
}
```

Отмена не отдельное поле: команда обязана выполняться через
`history.execute()` и потому обратима по построению. Команда, которая правит
документ мимо истории, — ошибка, и её ловит контрактный тест (см. 6.3).

### 4.4 Правило

```ts
export interface RuleDefinition {
  id: string;
  order: number;               // порядок применения детерминирован
  applies(edit: PixelEdit, ctx: RuleContext): boolean;
  /** Преобразует правку. Вето — вернуть null. */
  transform(edit: PixelEdit, ctx: RuleContext): PixelEdit | null;
}
```

Первые правила, которые переезжают сюда из разных мест кода:

1. `selection-confines-edits` — из `confineToSelection`
2. `lock-transparent-pixels` — из `paintMask`
3. `lock-pixels` / `lock-position` — сегодня разбросано
4. `layer-kind-guard` — из `RASTER_ONLY_TOOLS`
5. `clipping-mask-bounds`

**Урок, который надо закрепить.** Точка-предохранитель для выделения
существовала, но одна строка (`commitRevision`) дотянулась мимо неё к
необрезанному буферу: экран показывал обрезанное, а redo вернул бы полное.
Починено коммитом `b7c1f84`. Вывод для движка правил: недостаточно иметь
единственное место проверки — до **всех** потребителей (экран, история,
хранилище, экспорт) должен доходить **один и тот же объект**. Это проверяемое
свойство, и на него нужен тест.

### 4.5 Элемент интерфейса

Атомы — с полным поведением, а не «просто input».

- **`NumberBox`** — ввод цифрами; стрелки ↑↓; колесо мыши; перетаскивание вверх-вниз
  с зажатой ЛКМ; `Shift` — крупный шаг, `Alt` — мелкий; принимает единицы
  (`1 см`, `1 px`, `1 пикс`, `10%`) и приводит их по текущим настройкам
  документа; `Esc` — откат к значению до правки.
- **`Slider`** — почти всегда в паре с `NumberBox`, двусторонняя связь; `Alt` —
  точный режим; двойной клик — значение по умолчанию.
- **`Curve`** — интерактивная, точки добавляются/удаляются/тащатся,
  используется коррекциями и Camera Raw.
- **`Histogram`** — интерактивная там, где задаёт уровни.
- **`EyedropperButton`** — временно включает инструмент пипетки и возвращает
  цвет **в вызвавшее окно**, после чего восстанавливает прежний инструмент.
- **`ValueBadge`** — плашка с числом у курсора (размеры при трансформации);
  единица измерения берётся из настроек, а не зашита.

Правило для всех оверлеев: **интерфейс не масштабируется зумом**. Размеры — в
экранных пикселях. Единственное исключение — след инструмента (кольцо кисти),
потому что он показывает реальный отпечаток. Проверяется тестом.

## 5. Этапы

Каждый заканчивается зелёными тестами и работающим приложением.

### Этап 0. Замки

Перекладка без страховки — это разрушение. Сначала страховка.

- [x] Бенчмарк композита, перемещения, обрезки правки по границам и памяти
      слоёв — `packages/env-raster/src/performance.bench.test.ts`;
      автосохранения — `packages/kernel/src/performance.bench.test.ts`.
      Цифры перемерены на текущем коде, а не взяты из памяти:

      | операция | старая цифра (из памяти) | перемерено сейчас | как задан порог |
      |---|---|---|---|
      | композит 21 слоя 1920×1080 | ~14 мс | **~27 мс** | ×6 от измеренного |
      | перемещение слоя (block-copy) | ~14 мс/кадр | **~0.7 мс** | абсолютный пол 5 мс |
      | обрезка правки по границам | — | **~8 мс** | ×6 от измеренного |
      | автосохранение (1 из 21 буфера) | ~8 мс | **<1 мс** | абсолютный пол 5 мс |
      | память пикселей, 21 слой | ~3.1 МБ | **~13.4 МБ** на этой фикстуре | <30% от «все слои в размер холста» |

      Старая цифра композита (14 мс) не подтвердилась — либо была измерена на
      документе с более компактными слоями, либо ошибочно перенесена из
      контекста предыдущей сессии. **CLAUDE.md и раздел 2 этого документа
      обновлены**: 14 мс убрано как факт, оставлено только со ссылкой на то,
      что оно непроверенное.

      Первая версия фикстуры сама была неправильной: все 21 слой на весь
      холст непрозрачным цветом с дробной прозрачностью — это заставляет
      каждый пиксель идти по самой медленной ветке блендинга на каждом слое
      сразу, и дало бессмысленные ~500 мс. Слои по всему холсту вообще
      противоречат сути самой оптимизации (166→3.1 МБ достигнуты именно
      потому, что реальные слои не занимают весь холст). Исправлено:
      единственный фон на весь холст + 20 слоёв реального размера мазка,
      проведённых через `setLayerPixels`/`trimToContent`, как это делает
      настоящая правка.

      Порог памяти получил аналогичную правку: первая версия требовала
      «меньше 10 МБ» — число, придуманное не глядя на то, что один фоновый
      слой на 1920×1080 уже весит 8.3 МБ. Заменено на структурное сравнение

      зарезервированных 7 языков, а объект с двумя обязательными полями не
      способен её выразить — пришлось бы либо дублировать английский текст в
      несуществующие переводы, либо снова переделывать формат при первом
      реальном добавлении языка, то есть ровно то «дважды», ради которого
      существует этот этап
- [x] `i18n.ts`: добавлены `LocalizedText`, `resolveLabel` (выбор строки с
      падением на английский) и `legacyBilingualLabel` (сборка строки
      `"English (Русский)"` из структурированных данных для команд ядра —
      `CommandRegistry.search()` ищет по сырому `Command.label`, а команды
      регистрируются один раз при старте, а не читаются заново при каждом
      рендере, как `ToolDefinition` — значит, живое переключение языка и
      поиск на любом языке должны продолжать работать без переизобретения
      контракта `Command` в ядре прямо сейчас; это сознательно отложено до
      этапа 7, когда каталог команд и так переезжает в отдельные файлы).
      Обошлись без отдельного словаря по ключам — не потому что он хуже, а
      потому что тот же fallback-контракт получается из одного поля

      заполненным только `en`

**Побочно найденный и исправленный баг**: `registerToolShortcuts()` строил
подпись команды переключения инструмента как `group.map(tool =>
tool.label).join(" / ")` — то есть склеивал уже двуязычные строки вида
`"Blur Tool (Размытие)"` через `/`, а `localized()`'s regex (`^(.*?)\(([^()]*)\)$`)
матчит только ПОСЛЕДНЮЮ скобочную пару во всей строке. Для группы на букву R
(Blur+Smudge) результат на русском показывал только «Палец», теряя «Размытие»,
а на английском в подпись затесывался обрывок русского текста. Починено как
прямое следствие смены формата (`resolveLabel(tool.label, "en").join(...)` /
`resolveLabel(tool.label, "ru").join(...)` раздельно, затем
`legacyBilingualLabel`) — проверено вживую через `kernel.commands.list()`:
`tool.raster.r` теперь корректно показывает все три инструмента группы на
обоих языках.

**Проверено вживую** (свежий dev-сервер, не унаследованный от предыдущей
сессии — на старом сервере всплыла ложная тревога: `label.match is not a
function`, которая существовала ещё ДО этого этапа, то есть являлась
застоявшимся артефактом HMR за много часов правок, а не регрессией; после
перезапуска сервера на чистом коде ошибки нет ни до, ни после стадии 1):

настройках (там подписи команд по-прежнему показывают сырую двуязычную
строку без вызова `localized()` — это существовавшее до этапа 1 поведение,
не регрессия, сохранено байт в байт через `legacyBilingualLabel`).

   Ни одной правки в другом месте.

3. Новая среда — **один подкаталог** с `environment.ts`.
4. `RasterWorkspace.tsx` ≤ 400 строк; ни одного `activeToolId === "..."`.
5. Ни одна цифра из раздела 1 не ухудшилась.
6. Приложение открывается в браузере, `.exe` на Windows и `.app` на macOS из
   одного кода.
